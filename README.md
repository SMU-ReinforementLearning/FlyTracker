# FlyTracker

시야각이 제한된 조준기가 방 안을 나는 초파리를 겨누는 강화학습 환경이다. 조준기는 정해진 자리에서 조준 방향만 돌리는 카메라이고, 자기 화면에 들어온 것만 안다. 추격 한 판이 에피소드다. 기준선은 사람이 짠 규칙으로 움직이는 조준기다. 학습한 조준기 agent는 기준선과 견주고, 결과는 웹 페이지인 viewer에서 3인칭 장면과 조준기 화면으로 재생한다. 초파리 자리에도 피하는 법을 학습하는 초파리 agent를 넣을 수 있어서, 조준기 agent와 초파리 agent를 번갈아 학습해 맞붙인다.

저장소는 세 부분으로 되어 있다. Python 쪽(환경, 학습 코드)과 viewer는 서로를 부르지 않는다. 에피소드를 돌리고 재생하는 동안 둘을 잇는 것은 `runs/`와 `published/` 폴더의 에피소드 파일뿐이다. 에피소드 파일은 에피소드 하나를 담은 JSON 파일이다.

| 부분 | 폴더 | 하는 일 |
|---|---|---|
| [환경](#환경) | `flytracker/` | 초파리와 조준기를 움직이고 관측과 보상을 돌려준다. 기준선도 여기 있다 |
| [학습 코드](#학습-코드) | `scripts/` | 기준선이나 학습 중인 조준기 agent, 초파리 agent로 에피소드를 돌려 `runs/`에 저장한다. 버전끼리 맞붙이는 대전표 스크립트, 실행을 `published/`에 복사하는 스크립트와 viewer의 초파리 3D 모델을 만드는 스크립트도 여기 있다 |
| [viewer](#viewer) | `viewer/` | `runs/`와 `published/`의 에피소드를 3D로 재생한다 |

## 시작하기

결과만 볼 때는 https://flytracker-ewk.pages.dev/ 를 연다. 저장소에 올린 실행이 재생된다. 직접 돌리려면 Python 3.10 이상, [uv](https://docs.astral.sh/uv/), Node 20.19 이상이 필요하다.

```sh
git clone https://github.com/SMU-ReinforementLearning/FlyTracker.git
cd FlyTracker
uv sync --extra train --extra dev
uv run python scripts/record_baseline.py --episodes 5
npm install --prefix viewer
npm run dev --prefix viewer
```

브라우저에서 http://localhost:5180 을 연다. 왼쪽 목록에 방금 돌린 실행과 저장소에 올라 있는 실행이 보인다. 실행은 스크립트를 한 번 돌려 생긴 결과 전체다. 실행 안의 에피소드를 고르면 바로 재생된다.

`train` extra는 Stable-Baselines3와 TensorBoard를, `dev` extra는 pytest를 설치한다. 기준선만 돌릴 때는 `uv sync`로 충분하다. 신경 모델을 포함한 전체 테스트는 `uv sync --extra neural --extra dev`로 의존성을 설치한 뒤 `uv run python -m pytest -q`로 돌린다.

Claude Code, Codex, ChatGPT desktop 같은 AI 코딩 도구로 작업할 때 지킬 규칙은 `AGENTS.md`에 있다. Claude Code는 `claude`를 띄우고 채팅에 `run onboarding`이라고 입력하면 저장소의 git hook과 Claude Code hook을 켜고 Node와 GitHub CLI가 있는지 확인한다. 다른 AI 코딩 도구는 `AGENTS.md`를 읽게 하고, git hook은 `git config core.hooksPath .githooks`로 직접 켠다. 코드만 돌려 볼 때는 건너뛰어도 된다.

## 환경

조준기 쪽 환경은 `flytracker/env.py`의 `FlyChaseEnv`다. [Gymnasium](https://gymnasium.farama.org/) 규격을 따르고, 초파리 비행, 조준기 회전, 초파리가 화면에 보이는지 계산하는 부분은 numpy로 직접 짰다. 물리 엔진은 쓰지 않는다. 조준기 agent가 행동을 하나 고르면 환경은 0.02초를 진행하고 관측과 보상을 돌려준다. 이 한 번이 step이다.

학습하는 쪽은 조준기와 초파리 둘이다. 조준기 agent는 `FlyChaseEnv`에서, 초파리 agent는 `flytracker/fly_env.py`의 `FlyEscapeEnv`에서 학습한다. 두 환경은 같은 시뮬레이션을 쓰고, 상대 자리에는 규칙으로 움직이는 상대나 학습을 멈춘 모델이 들어간다. 아래에서 방과 좌표부터 에피소드까지 네 절은 둘이 함께 쓰는 부분이다. 그 뒤로 조준기 쪽 두 절(state와 action, R)은 조준기 agent에게, 초파리 쪽 두 절은 초파리 agent에게만 해당한다. 마지막 절은 두 환경이 따르는 Gymnasium 규격이다.

### 방과 좌표

방은 가로 4m, 높이 2.5m, 깊이 3m다. 좌표는 x 오른쪽, y 위, z 정면인 오른손 좌표이고 단위는 m, 원점은 바닥 중심이다. three.js도 같은 축을 쓰므로 viewer는 좌표를 변환하지 않는다.

### 조준기

조준기는 방공포처럼 자리가 고정되어 있고, 자리를 옮기지 않고 yaw와 pitch만 돌린다. 기본 자리는 바닥 정가운데이고 회전축 높이는 0.1m다. 세로 시야각은 기본 40°, 화면 비율은 4:3이다. 조준기 자리를 정하는 설정 `turret_pos`와 옵션 `--turret-pos`만 `turret`이라 부르고, 나머지 코드와 옵션, 에피소드 파일은 `aimer`라고 부른다.

### 초파리

초파리는 실제 초파리의 자유비행 측정값을 따라 난다. 직선 구간과 급선회를 번갈아 하고, 직선 구간은 짧은 것이 잦고 긴 것이 드물다. 속도는 평균 약 0.3m/s이고, 급선회는 평균 93°를 약 50ms에 돈다.

피하는 법은 두 가지다. 규칙 초파리는 사람이 짠 규칙으로 피한다. 규칙 초파리에는 평시와 비상시가 있다. 초파리가 조준기에 1m 안에서 지금 속도로 1초 안에 닿을 만큼 빠르게 가까워지거나, 0.35m 안으로 들어가면 조준기를 위협으로 느껴 비상시로 바뀐다. 비상시가 되면 60ms 뒤 조준기 반대쪽으로 빠르게 돌며 잠깐 빨라진다. 규칙 초파리는 조준기가 자기를 겨누는지 모른다.

초파리 agent는 평시 비행(직선 구간과 급선회)은 규칙 초파리와 같고, 언제 어느 쪽으로 얼마나 빨리 피할지만 스스로 정한다. 조준기에서 조준 방향으로 초록 레이저 빔이 나간다고 가정해서, 초파리 agent는 조준 방향을 본다. 초파리는 빨간빛을 잘 보지 못하고 초록빛은 잘 보기 때문에 초록으로 정했다. 무엇을 보고 무엇을 정하는지는 [초파리의 state와 action](#초파리의-state와-action)에 있다. 규칙 초파리가 조준 방향을 모른다는 것과 초파리 agent가 레이저 빔을 본다는 것은 2026-11-12 기준 가정이고 바뀔 수 있다.

비행 값에는 문헌에서 가져온 값과 가정한 값이 섞여 있다. 값마다 출처는 [초파리 비행 모델과 기준선 탐색](docs/issues/feature/9-feature-fly-realism-search/fly-flight-and-search-model.md)에 있고, `flytracker/fly.py`의 `FlyParams`에서 바꾼다.

### 신경 초파리

신경 초파리는 초파리 뇌의 실제 신경 연결 일부를 계산해서 나는 세 번째 초파리다. 뉴런 547개와 연결 16,344개로 발화를 계산하고, 그 발화에서 날개 힘을 구해 몸을 움직인다. 연결은 측정 자료에서 가져왔지만 어느 뉴런을 고를지와 발화에서 날개 힘으로 바꾸는 식은 가정이다. 가중치를 학습한 결과가 아니고, 실제 초파리의 움직임과 맞는지는 확인하지 않았다.

기본은 규칙 초파리이고 `--fly-model neural`을 주면 신경 초파리로 바뀐다. 실행 코드와 필요한 신경 자료는 `flytracker/neural_assets`에 포함돼 있어 별도 프로젝트나 환경 변수 없이 실행한다. `--neural-source`와 `FLYTRACKER_NEURAL_SOURCE`는 외부 원본을 의도적으로 선택할 때만 사용한다. 자료의 저작자표시 및 비영리 조건은 [동봉 고지](flytracker/neural_assets/NOTICE.md)를 확인한다.

```sh
uv sync --extra neural --extra dev
uv run python scripts/record_baseline.py --fly-model neural --episodes 1 --seed 10000 --no-save
```

| 구성 | 출처 | 저장소에 들어 있나 |
|---|---|---|

저장소에 올린 신경 초파리 실행은 세 개이고, viewer의 [issue #31 화면](https://flytracker-ewk.pages.dev/?issue=31)에서 재생한다. 재생에는 flysim이 필요 없다. 세 실행은 2026-11-12에 예전 포획 조건(조준 방향에서 3° 안에 0.2초)으로 만든 기록이다.

필요한 파일과 실행 명령은 [flysim 출처와 실행](docs/issues/feature/31-feature-neural-flight/flysim-source.md)에, 모델의 가정은 [신경 날개 비행](docs/issues/feature/31-feature-neural-flight.md)에 있다.

### 에피소드

에피소드는 `reset`으로 시작해서 포획하거나 시간 초과로 끝난다.

1. 시작: 초파리를 조준기에서 1.5m 이상 떨어진 무작위 위치에 놓는다. 조준기는 기본 자리에서 −z 쪽을 수평으로 바라보며 시작한다. 자리를 옮기면 그 자리에서 방 가운데 쪽을 본다.
2. step: 환경은 행동을 유지한 채 0.01초씩 두 번, 합쳐 0.02초를 움직인다. 에피소드 파일에는 step마다 프레임 하나가 남는다.
3. 끝: 조준기가 쏜 한 발이 0.15초 내내 초파리에 맞으면 포획이다. 맞았다는 것은 초파리 몸 중심이 레이저 빔에서 1.25mm 안에 있다는 뜻이다. 빔은 조준기에서 조준 방향으로 나가는 직선이다. 10초가 지나면 시간 초과다. 포획 거리를 주면 초파리가 그 거리 안에 있어야 포획이 되는데, 기본으로는 없다.

포획은 레이저가 초파리에 맞는 것이다. 빔 지름은 2.5mm, 출력은 500mW로 가정했고, 0.15초는 그 출력으로 초파리를 죽이는 데 걸린다고 계산한 시간이다. 두 값의 근거와 확인되지 않은 점은 [레이저 포획 조건](docs/issues/feature/42-feature-laser-hit-capture/laser-capture-condition.md)에 있다. 1.25mm는 2m 거리에서 약 0.036°다. 2026-11-15 전에는 포획이 "조준 방향에서 3° 안에 0.2초"였고, 그때 저장한 실행은 그 조건으로 돌린 것이다.

레이저는 쏠 때만 나간다(환경 버전 6, #69). 조준기가 쏘면 한 발이 0.15초 동안 이어지고, 도중에 끌 수 없다. 그 0.15초 가운데 한 번이라도 빔이 초파리를 벗어나면 그 발은 오발이고 초파리는 잡히지 않는다. 한 발이 끝나면 바로 다시 쏠 수 있고, 쏘는 횟수에는 제한이 없다. 쏘는 동안에도 조준기는 돌 수 있다. 환경 버전 5까지는 레이저가 늘 켜져 있다고 보고, 빔이 1.25mm 안에 0.15초 머물면 포획으로 쳤다. 에피소드마다 쏜 발 수와 오발 수를 센다. 오발은 빔이 초파리가 아닌 곳에 닿은 발이다.

발사는 조준기의 일이다. 쏠지는 조준기가 정하고, 한 발의 길이 0.15초는 레이저 장치의 값이다. 환경은 그 발이 초파리에 맞았는지만 판정한다. 설정 파일에서는 한 발의 길이가 예전 이름 그대로 `capture_hold`에 있다.

그래서 에피소드 하나는 길어야 500 step이고, 시작 직후 프레임까지 더해 프레임은 최대 501개다. seed가 같으면 시작 위치가 같다. 규칙 초파리는 고정된 조준기의 자리에만 반응하고 조준 방향은 모르므로, 조준기 정책이 달라도 같은 seed에서 같은 경로로 난다. 초파리 agent는 레이저를 보고 피하므로, 조준기 정책이 다르면 경로도 달라진다.

### 조준기의 state와 action

state는 조준기 agent가 step마다 받는 관측이고 18차원이다. 초파리가 안 보일 때 state에 남는 초파리 정보는 마지막으로 본 방향과 놓친 뒤 지난 시간뿐이다. 어떤 항목을 넣을지는 2026-11-17 기준으로 정한 가정이고, 필요에 따라 맞다고 보는 방향으로 바꿀 수 있다.

| 항목 | 차원 |
|---|---|
| 초파리가 보이는지 | 1 |
| 화면 좌표와 거리. 보일 때만 값이 있고 안 보이면 0 | 3 |
| 초파리 방향의 각속도. 보일 때만 값이 있고 안 보이면 0 | 2 |
| 가운데를 확대한 조준 오차. 보일 때만 값이 있고 안 보이면 0 | 2 |
| 마지막으로 본 방향 | 3 |
| 놓친 뒤 지난 시간. 2초에서 더 늘지 않는다 | 1 |
| 조준기의 yaw(sin과 cos)와 pitch | 3 |
| 조준기의 yaw와 pitch 각속도 | 2 |
| 쏘는 중인 한 발의 남은 시간 | 1 |

- 초파리가 보이는지: 초파리가 조준기 화면 안에 들어오면 1, 아니면 0이다.
- 화면 좌표와 거리: 화면 좌표는 화면 안에서 초파리가 있는 자리다. 가로세로 −1~1이고 오른쪽과 위가 +다. (0, 0)이 화면 한가운데, 곧 조준 방향이다. 거리는 조준기에서 초파리까지 거리를 방 대각선 길이(약 5.6m)로 나눈 값이다.
- 초파리 방향의 각속도: 조준기에서 본 초파리 방향이 yaw와 pitch로 도는 빠르기를 조준기의 최고 각속도(yaw 180°/s, pitch 120°/s)로 나눈 값이다. action과 눈금이 같아서, 이 값을 그대로 action으로 내면 조준기가 초파리와 같은 빠르기로 돈다. 2m 거리에서 0.3m/s로 나는 초파리는 약 8.6°/s로 움직이고, 값으로는 약 0.05다. 지금은 오차 없는 참값을 준다. 화면 좌표를 오차 없이 주는 것과 같은 수준의 가정이고, 검출 오차를 넣을 때(#13) 추정값으로 바꾼다.
- 가운데를 확대한 조준 오차: 초파리가 화면 가운데에서 벗어난 각도(가로, 세로)를 0.5°로 나눈 값이다. 0.5° 넘게 벗어나면 −1이나 1이다. 레이저 명중은 2m 거리에서 0.036° 안이어야 하는데, 화면 좌표로는 0.002 차이라서 학습이 가려내기 어렵다. 이 값으로는 약 0.07이다.
- 마지막으로 본 방향: 초파리를 마지막으로 본 자리가 지금 조준기에서 어느 쪽에 있는지를 오른쪽, 위, 앞 세 값으로 나타낸다. 조준기가 돌면 값도 따라 바뀌므로, 그 자리를 다시 보려면 어느 쪽으로 돌아야 하는지 바로 알 수 있다. 초파리가 보이는 동안에는 지금 초파리가 있는 방향과 같고, 한 번도 못 봤으면 0이다.
- 놓친 뒤 지난 시간: 지난 시간을 2초로 나눈 값(0~1)이다. 초파리가 보이는 동안은 0이고, 한 번도 못 봤으면 1이다.
- 조준기의 yaw(sin과 cos)와 pitch: 조준기가 바라보는 방향이다. yaw는 한 바퀴를 돌 수 있어서 359°와 1°가 바로 옆인데, 각도를 그대로 넣으면 두 값이 멀리 떨어진다. sin과 cos로 넣으면 이 끊김이 없다. pitch는 위아래 90°까지만 돌므로 90°로 나눈 값 하나로 넣는다.
- 조준기의 yaw와 pitch 각속도: 조준기가 지금 실제로 도는 빠르기를 최고 각속도(yaw 180°/s, pitch 120°/s)로 나눈 값이다. 실제 각속도는 action이 정한 목표 각속도를 따라가는 중이라, action과 다를 수 있다.
- 쏘는 중인 한 발의 남은 시간: 남은 시간을 0.15초로 나눈 값(0~1)이다. 쏘고 있지 않으면 0이고, 0일 때만 새로 쏠 수 있다.

</details>

action은 −1~1 범위의 3차원 행동이다. 앞의 둘은 yaw와 pitch의 목표 각속도이고, 1이 yaw 180°/s, pitch 120°/s다. 셋째는 발사이고, 0보다 크면 한 발 쏜다. 쏘는 중에 다시 0보다 큰 값을 내도 새 발이 나가지 않는다. 실제 각속도는 목표를 향해 1초에 720°/s까지만 바뀌므로, 멈춘 상태에서 최고 속도까지 0.25초가 걸린다. pitch는 위아래 90°까지 돌아서 조준기 바로 위에도 빔이 닿는다. DQN처럼 이산 행동만 받는 알고리즘을 위해 행동 6개짜리 wrapper가 있다. 차례로 정지, yaw 왼쪽, yaw 오른쪽, pitch 위, pitch 아래, 발사다.

### 조준기의 R

R은 조준기 agent가 step마다 받는 보상이다. 포획 보상을 빼면 모두 벌점이다. 빔까지 거리는 초파리 몸 중심에서 빔 중심선까지의 거리이고, 누적 보상은 에피소드 동안 받은 보상의 합이다.

| 항목 | 가중치 |
|---|---|
| 시간 벌점 | step마다 0.01 |
| 놓친 벌점 | 초파리가 안 보이는 step마다 0.15 |
| 빔까지 거리 벌점 | 초파리가 보이는 step마다 빔까지 거리의 log 눈금으로 0~0.1. 빔 위에서 0, 1m 이상이면 0.1 |
| 행동 변화 벌점 | 직전 행동과 이번 행동의 차이를 yaw와 pitch마다 제곱해 평균한 값 × 0.01 |
| 포획 보상 | 10 |

<details>
<summary>항목별 설명</summary>

놓친 벌점과 빔까지 거리 벌점은 한 step에 둘 중 하나만 받는다.

- 시간 벌점: 무엇을 하든 step마다 받는다. 포획이 늦을수록 쌓이므로 빨리 포획할수록 누적 보상이 커진다.
- 놓친 벌점: 초파리가 화면 밖에 있는 step마다 받는다. 빔까지 거리 벌점의 최댓값 0.1보다 1.5배 크므로, 화면 가장자리에라도 두는 편이 놓치는 것보다 낫다.
- 빔까지 거리 벌점: 0.1 × log(1 + 거리 ÷ 1.25mm) ÷ log(1 + 1m ÷ 1.25mm)이다. 1.25mm는 포획 반경이다. 거리가 10분의 1로 줄 때마다 거의 같은 만큼 준다. 125mm에서 0.069, 12.5mm에서 0.036, 1.25mm에서 0.010, 빔 위에서 0이다. 환경 버전 4까지는 조준 오차(각도)에 비례하는 벌점이었고, 1° 아래로는 거의 달라지지 않아서 빔을 mm 단위로 붙이는 데에는 신호가 되지 못했다. 그 벌점은 `--reward beam=0 angle=0.05`로 다시 켤 수 있다.
- 행동 변화 벌점: 행동을 갑자기 바꿀수록 커진다. 조준기가 떨지 않고 부드럽게 돌게 하려는 벌점이다. yaw를 −1에서 1로 한 번에 바꾸고 pitch는 그대로 두면 (2² + 0²) ÷ 2 × 0.01 = 0.02다. 에피소드 첫 step은 직전 행동을 0으로 본다.
- 포획 보상: 포획한 step에 한 번 받고, 그 step으로 에피소드가 끝난다. 포획 조건은 [에피소드](#에피소드)에 있다.

</details>

벌점 가운데 놓친 벌점이 가장 크므로 빨리 찾을수록 누적 보상이 커진다. 초파리가 보이는 동안에도 양(+)의 보상은 없다. 보이는 step마다 양의 보상을 주면, 포획해서 에피소드를 끝내기보다 초파리를 화면에 두고 오래 버티는 편이 누적 보상이 커질 수 있어서다. 항목과 가중치는 2026-11-12 기준으로 정한 가정이고, 필요에 따라 맞다고 보는 방향으로 바꿀 수 있다. 가중치는 `flytracker/env.py`의 `RewardWeights`에서 바꾼다.

### 초파리의 state와 action

state는 초파리 agent가 step마다 받는 관측이고 17차원이다. 모든 값은 0.06초(3 step) 전의 것이다. 규칙 초파리가 위협을 느끼고 피하기 시작할 때까지 걸리는 60ms와 같은 값이다. 어떤 항목을 넣을지는 2026-11-12 기준으로 정한 가정이고, 초파리 agent를 맡은 사람이 맞다고 보는 방향으로 바꾼다. 항목은 두 환경이 함께 쓰는 `flytracker/env.py`의 `FLY_OBS_FIELDS`에 있다.

방향은 초파리 몸을 기준으로 오른쪽, 위, 앞 세 값으로 나타낸다. 앞은 나는 방향을 수평으로 눕힌 방향이고, 위는 방의 위쪽이다.

| 항목 | 차원 |
|---|---|
| 조준기가 있는 방향과 거리 | 4 |
| 초파리에서 가장 가까운 레이저 빔 위의 점의 방향과 거리 | 4 |
| 조준 오차 | 1 |
| 오르내림과 속도 | 2 |
| 방 안 위치 | 3 |
| 나는 방향(sin과 cos) | 2 |
| 지금 피할 수 있는지 | 1 |

<details>
<summary>항목별 설명</summary>

- 조준기가 있는 방향과 거리: 거리는 방 대각선 길이(약 5.6m)로 나눈 값이다. 조준기는 자리가 고정되어 있어서, 이 값은 초파리가 움직일 때만 바뀐다.
- 초파리에서 가장 가까운 레이저 빔 위의 점의 방향과 거리: 거리는 방 대각선 길이로 나눈 값이다. 레이저 빔은 조준기에서 조준 방향으로만 나간다. 그래서 초파리가 조준기 뒤쪽에 있으면 가장 가까운 점은 조준기 자리다. 초파리가 레이저 빔 위에 있으면 방향은 0이다.
- 조준 오차: 조준기에서 본 초파리 방향과 조준 방향 사이의 각도를 180°로 나눈 값이다. 포획과 R은 이 각도가 아니라 빔까지 거리를 쓴다.
- 오르내림과 속도: 오르내림은 나는 방향의 위아래 성분을 최댓값 0.4로 나눈 값이다. 속도는 지금 속도를 1.6m/s로 나눈 값이다. 지금 속도에는 피한 직후 빨라진 몫도 들어간다. 1.6m/s는 평시 최고 속도 1.0m/s에 피한 직후의 최대 배율 1.6을 곱한 값이다.
- 방 안 위치: 축마다 양쪽 벽이 −1과 1이다.
- 나는 방향: 수평 각도를 sin과 cos로 넣는다. 각도는 −z 쪽이 0°이고, 위에서 볼 때 반시계 방향이 +다. 조준기의 yaw와 같은 규약이다.
- 지금 피할 수 있는지: 직전 회피 뒤 0.4초가 지났으면 1이다. 이 값도 0.06초 늦게 받는다. 그래서 피하기 시작한 직후 3 step 동안은 실제로는 피할 수 없는데도 1로 보이고, 그동안 내린 회피 명령은 무시된다.

</details>

action은 −1~1 범위의 4차원 행동이다. 평시 비행은 규칙 초파리와 같은 규칙을 따르고, action은 회피만 정한다. 항목은 `FLY_ACTION_NAMES`에 있다.

| 항목 | 뜻 |
|---|---|
| 회피 | 0보다 크면 지금 피한다. 직전 회피 뒤 0.4초가 지나지 않았으면 무시한다 |
| 선회각 | × 180°. 지금 나는 방향에서 수평으로 돌 각도이고, +가 왼쪽이다 |
| 오르내림 | × 0.4. 피하는 방향의 위아래 성분이다 |
| 속도 배율 | −1이면 1배, 1이면 1.6배다. 피한 직후 0.3초 동안 이 배율로 빨라진다 |

피하는 선회는 규칙 초파리가 피할 때처럼 25ms에 끝난다. 평시 급선회(약 50ms)보다 빠르다. 피하는 선회 시간, 빨라지는 시간, 다시 피할 수 있을 때까지의 시간, 속도 배율의 상한은 `FlyParams` 값을 그대로 쓴다. 물리적으로 그럴듯한 범위는 초파리 agent를 맡은 사람이 정한다.

### 초파리의 R

R은 초파리 agent가 step마다 받는 보상이다. 조준기의 R에서 부호를 뒤집은 값이고, 행동 변화 벌점은 조준기에만 해당해서 뺐다.

| 항목 | 가중치 |
|---|---|
| 시간 보상 | step마다 0.01 |
| 안 보인 보상 | 조준기에 안 보이는 step마다 0.15 |
| 빔까지 거리 보상 | 조준기에 보이는 step마다 빔까지 거리의 log 눈금으로 0~0.1. 조준기의 빔까지 거리 벌점과 같은 값 |
| 포획 벌점 | 10 |

포획 벌점을 빼면 모두 양(+)의 보상이다. 그래서 오래 버틸수록, 조준기 화면 밖에 있을수록 누적 보상이 커진다. 빔까지 거리 보상은 2026-11-15에 조준기의 R을 바꾸면서 같이 바꿨다(환경 버전 5). 항목과 가중치는 2026-11-12 기준으로 정한 가정이고, 초파리 agent를 맡은 사람이 `flytracker/env.py`의 `FlyRewardWeights`에서 바꾼다.

## 학습 코드

`scripts/`에서 에피소드를 돌리는 스크립트는 네 개다. `record_baseline.py`는 기준선으로, `train.py`는 학습 중인 조준기 agent나 초파리 agent로 에피소드를 돌려 `runs/`에 저장한다. `record_match.py`는 기준선이나 이미 학습한 조준기 모델을 고른 환경 옵션에서 돌려 `runs/`에 저장한다. `match.py`는 `runs/`에 저장하지 않고, 조준기와 초파리를 맞붙인 [대전표](#대전표)를 출력한다. 넷 다 같은 [환경 옵션](#환경-옵션)을 받는다.

### 기준선

기준선은 조준기 agent와 같은 18차원 관측만 받고, 초파리의 실제 위치는 보지 않는다(`flytracker/baseline.py`). 보이면 관측의 초파리 방향 각속도에 맞춰 돌면서, 남은 조준 오차에 비례해 더 돌린다. 오차에만 비례해 돌리면 움직이는 초파리를 늘 조금 뒤에서 따라가서, 빔을 1.25mm 안에 붙이지 못한다. 관측의 거리와 조준 오차로 어림한 빔까지 거리가 1.25mm 안이면 한 발 쏜다. 놓치면 마지막으로 본 방향 둘레를 8자(숫자 8 모양)로 넓혀 가며 찾는다. 그래도 없으면 yaw를 한 바퀴 돌려 360°를 훑고, 한 바퀴마다 pitch를 세로 시야각보다 조금 좁은 간격으로 옮긴다. 어디까지 찾았는지는 기준선이 내부 상태로 기억한다.

이 README에서 탐색은 놓친 초파리를 찾는 동작을 가리키고, 강화학습의 exploration과는 다르다. 탐색은 기준선의 규칙일 뿐 환경의 관측, 보상, 행동에는 들어 있지 않으므로, 조준기 agent는 찾는 법도 스스로 배운다.

```sh
uv run python scripts/record_baseline.py --episodes 5
```

에피소드 i의 seed는 `--seed` 값에 i를 더한 것이고, `--seed`의 기본값은 0이다. `--no-save`는 저장하지 않고 요약만 출력한다.

### 학습

`train.py`는 Stable-Baselines3로 조준기 agent나 초파리 agent를 학습한다. `--algo`는 `sac`(기본), `td3`, `ppo`, `dqn` 중 하나다. 조준기 agent는 DQN이면 이산 행동 6개, 나머지면 연속 행동 3차원으로 학습한다. 초파리 agent는 연속 행동 4차원이라 DQN을 쓸 수 없다. 정책은 MLP다. 나머지 옵션은 `--help`로 본다.

```sh
uv run python scripts/train.py --algo sac --steps 200000 --eval-every 20000
uv run tensorboard --logdir runs
```

`--side`는 학습할 쪽이고 기본은 `aimer`(조준기)다. `fly`를 주면 초파리 agent를 학습한다. `--opponent`는 학습하는 동안 고정해 둘 상대다. 조준기 쪽의 기본 상대는 `rule`(규칙 초파리), 초파리 쪽의 기본 상대는 `baseline`(기준선)이다. [실행 폴더](#실행-폴더)를 주면 그 안의 `model.zip`을, checkpoint 파일을 주면 그 모델을 상대로 쓴다. [환경 버전](#실행-폴더)이 지금 코드와 다른 모델은 상대로 불러오지 않는다.

```sh
uv run python scripts/train.py --side fly --opponent runs/<조준기 실행 id> --algo sac
uv run python scripts/train.py --side aimer --opponent runs/<초파리 실행 id>/checkpoints/step_0200000.zip
```

조준기 보상의 가중치는 `--reward 항목=값`으로 실행마다 바꿀 수 있다. 항목은 `flytracker/env.py`의 `RewardWeights`에 있는 이름이다. 바꾼 값은 `config.json`의 환경 설정에 남는다. `record_baseline.py`도 같은 옵션을 받는다.

```sh
uv run python scripts/train.py --algo sac --reward beam=0 angle=0.05
```

`--assist 값`을 주면 조준기 agent의 행동에 기준선의 추적을 더한다. 초파리가 보이는 동안 환경에 들어가는 행동은 기준선의 추적 행동에 `값 × agent의 행동`을 더한 것이고, 안 보이는 동안은 agent의 행동 그대로다. agent는 탐색을 온전히 맡고, 보이는 동안에는 추적을 고치는 보정만 배운다. 값은 `config.json`의 `algo.assist`에 남고, `match.py`와 상대로 불러올 때도 같은 방식으로 더한다. 환경은 그대로라서 환경 버전은 바뀌지 않는다.

```sh
uv run python scripts/train.py --algo sac --assist 0.2
```

`--control`은 조준기 agent의 돌리는 행동이 뜻하는 것을 정한다(#88). 기본인 `rate`는 각속도다. `accel`을 주면 각가속도이고, 지금 각속도에 `행동 × 각가속도 한계 × 0.02초`를 더한 값이 환경에 들어간다. 행동이 0이면 지금 속도로 계속 돈다. `--fire`는 쏠지를 누가 정하는지다. 기본인 `policy`는 agent가 정하고, `rule`을 주면 agent는 돌리는 두 값만 내고 쏠지는 기준선의 규칙이 정한다. 둘 다 환경 밖에서 행동을 바꾸는 것이라 환경 버전은 그대로다. 값은 `config.json`의 `algo.control`과 `algo.fire`에 남고, 상대로 불러올 때도 같은 방식으로 돌린다.

```sh
uv run python scripts/train.py --algo sac --control accel --fire rule --reward action_change=1.0
```

`--aim 실행 폴더`를 주면 조준은 그 폴더의 모델이 하고, agent는 쏠지만 학습한다. 조준 모델은 `--fire rule`로 학습한 것이어야 하고, 새 실행 폴더의 `aim/`에 복사된다. agent는 값 하나를 내고 0보다 크면 쏜다. `--fire-prior rule`을 함께 주면 기준선의 규칙이 쏘라고 할 때 +0.5, 아닐 때 −0.5를 그 값에 더한 뒤 0과 견준다. 그래서 값이 0이면 규칙과 똑같이 쏜다. 오발 한 발마다 빼는 벌점은 `--reward misfire=값`으로 주고 기본은 0이다.

```sh
uv run python scripts/train.py --algo sac --aim runs/<조준기 실행 id> --fire-prior rule --frame-stack 4 --reward misfire=1.0
```

학습 중 평가는 학습을 시작할 때와 그 뒤 일정 step마다 에피소드 몇 개를 저장하는 것이다. 간격은 `--eval-every`로 기본 20,000 step, 개수는 `--eval-episodes`로 기본 3개다. checkpoint는 그때마다 저장한 모델이다.

학습 중 평가는 매번 같은 seed를 쓴다. 첫 에피소드가 `--eval-seed`(기본 10000)이고 다음 에피소드부터 하나씩 커진다. 조준기 agent를 규칙 초파리 상대로 학습하면 초파리 경로까지 같아서, checkpoint끼리 같은 초파리를 상대로 비교된다. 초파리 agent가 끼면 경로는 정책마다 달라지고, 같은 것은 시작 위치까지다. 학습을 시작할 때 저장한 에피소드는 viewer에 "학습 전"으로 나오고, 그 뒤 것은 "20,000 step"처럼 나온다.

### 기준선과 비교

조준기 agent가 이겨야 할 기준선 성적은 아래와 같다. 상대는 규칙 초파리다. 학습 중 평가가 쓰는 seed 10000부터 에피소드 200개를 돌렸고, 환경 옵션과 보상 가중치는 기본값이다. 환경 버전은 6이고, 2026-11-17에 쟀다.

```sh
uv run python scripts/record_baseline.py --episodes 200 --seed 10000 --no-save
```

| 지표 | 기준선 |
|---|---|
| 포획 | 200개 중 200개 |
| 포획까지 평균 시간 | 4.99초 |
| 초파리가 보인 비율 | 31% |
| 평균 누적 보상 | −23.16 |
| 쏜 발 | 에피소드마다 평균 1.54발 |
| 오발 | 에피소드마다 평균 0.55발 |
| 오발 없이 잡은 에피소드 | 200개 중 134개 |

포획까지 걸린 시간은 대부분 초파리를 찾는 데 쓴다. 초파리가 화면에 들어온 뒤에는 각속도를 맞춰 빔을 붙이고, 빔이 1.25mm 안에 들어왔다고 보이면 쏜다. 쏜 발 수와 오발 수는 아래 명령으로 잰다. 쏘는 기준 거리를 바꿔 가며 잰 값은 [#69 관리 문서](docs/issues/feature/69-feature-aimer-fire-action-misfire.md)에 있고, 에피소드별, 발별 원자료와 다시 재는 명령은 [data 폴더](docs/issues/feature/69-feature-aimer-fire-action-misfire/data/README.md)에 있다.

```sh
uv run python docs/issues/feature/69-feature-aimer-fire-action-misfire/measure_fire.py --seed 10000
```

환경 버전 5에서는 레이저가 늘 켜져 있었고, 같은 seed에서 200개를 모두 포획했으며 평균 4.95초가 걸렸다. 버전 5는 환경 버전 4와 보상만 다르다. 기준선은 보상을 쓰지 않으므로 포획 수와 시간은 버전 4와 같고, 평균 누적 보상만 −19.95에서 −23.13으로 바뀌었다. 환경 버전 3의 기준선은 화면 좌표에만 비례해 돌았고, 같은 seed에서 200개 중 5개를 포획했다. 환경 버전 2(조준 방향에서 3° 안에 0.2초)에서는 200개를 모두 포획했고 평균 4.20초가 걸렸다. #35에서 학습한 SAC 모델 6개는 버전 2에서 약 97~98%를 포획했지만, 버전 3에서는 같은 seed로 합쳐 1,200개 가운데 1개를 포획했다.

환경 버전 5에서는 SAC로 조준기 agent를 네 조건으로 다시 학습했다(#51). 이 모델들은 쏘는 행동이 없던 때의 것이다. 환경 버전 6에서는 조준만 맡기고 쏠지는 기준선의 규칙으로 정해서 쓴다([조준기 v0과 v1](#조준기-v0과-v1)). 쏘는 것까지 학습한 결과는 [각가속도로 학습한 조준기](#각가속도로-학습한-조준기)에 있다. 보상은 빔까지 거리 벌점(기본값)과 조준 오차 벌점(`--reward beam=0 angle=0.05`) 두 가지이고, 추적 보조는 없음과 `--assist 0.2` 두 가지다. 조건마다 학습 seed 0, 1, 2로 1,000,000 step씩 학습했다. 학습을 마친 모델을 seed 20000부터 에피소드 200개에서 기준선과 견주었고, 2026-11-16에 쟀다. 평균 시간은 놓친 에피소드를 10초로 쳐서 낸 값이라 위 표의 포획까지 평균 시간과 다르다.

| 조준기 | 보상 | 추적 보조 | 포획 | 평균 시간 |
|---|---|---|---|---|
| 기준선 | 쓰지 않음 | | 200개 중 198개 | 4.86초 |
| SAC | 빔까지 거리 | 없음 | 600개 중 21개 | 9.92초 |
| SAC | 조준 오차 | 없음 | 600개 중 3개 | 9.98초 |
| SAC | 빔까지 거리 | 0.2 | 600개 중 585개 | 2.94초 |
| SAC | 조준 오차 | 0.2 | 600개 중 127개 | 8.98초 |

SAC 행은 모델 3개를 합친 값이다. 빔까지 거리 벌점에 추적 보조를 붙인 조건만 기준선보다 빨랐고, 학습 seed 3개 모두 그랬다. 다만 놓친 에피소드는 600개 중 15개로, 200개 중 2개인 기준선보다 비율이 높다. 나머지 세 조건은 1,000,000 step으로는 기준선에 못 미친다. 판정 기준과 결과는 [`gate.md`](docs/issues/feature/51-feature-sac-laser-training/gate.md)에 있다.

조준기 agent를 규칙 초파리 상대로 학습한 실행이면, viewer에서 학습 중 평가 에피소드 3개를 같은 seed의 기준선 에피소드 3개와 나란히 볼 수 있다. 기준선 쪽은 `record_baseline.py --episodes 3 --seed 10000`으로 만든다. seed가 같아야 같은 초파리를 상대로 비교되므로, `--seed`를 주지 않은 기준선(seed 0부터)과는 견주지 않는다. [시작하기](#시작하기)에서 만든 실행이 그 경우다. 에피소드 3개는 표본이 적어서 위 표의 200개 평균과 견주지 않는다. 포획 수와 포획 시간을 seed 200개로 견줄 때는 checkpoint를 [대전표](#대전표)의 `match.py`로 돌린다.

### 조준기 v0과 v1

조준기는 둘을 함께 둔다(#72).

- 조준기 v0은 기준선이다. 학습이 없어서 환경이 바뀌어도 바로 돌릴 수 있다. 변하지 않는 잣대로 쓴다.
- 조준기 v1은 #51에서 학습한 SAC 모델(빔까지 거리 벌점, 추적 보조 0.2, 학습 seed 0, 1, 2)에 기준선의 쏘는 규칙을 붙인 것이다. 조준은 모델이 하고, 관측으로 어림한 빔까지 거리가 1.25mm 안이면 쏜다. 모델은 쏘는 것을 배우지 않았고, 지금 쏘는 중인지도 보지 못한다.

v1은 규칙 초파리 상대로는 v0보다 빨리 잡는다. 신경 초파리 상대로는 평균 시간이 짧지만 놓치는 초파리가 훨씬 많고, 자극을 끄면 오발이 세 배다. v1은 규칙 초파리만 상대로 학습했다.

환경 버전 6에서 2026-11-18에 쟀다. v1의 값은 모델 셋의 평균이다. 평균 시간은 놓친 에피소드를 10초로 쳐서 냈다.

| 초파리 | 에피소드 seed | 조준기 | 포획 | 평균 시간 | 에피소드마다 오발 |
|---|---|---|---|---|---|
| 규칙 초파리 | 20000부터 200개 | v0 | 200개 중 198개 | 4.89초 | 0.50발 |
| 규칙 초파리 | 20000부터 200개 | v1 | 600개 중 584개 | 3.03초 | 0.60발 |
| 신경 초파리, 자극 끔 | 20000부터 60개 | v0 | 60개 중 59개 | 5.11초 | 0.62발 |
| 신경 초파리, 자극 끔 | 20000부터 60개 | v1 | 180개 중 155개 | 4.26초 | 1.94발 |
| 신경 초파리, 자극 켬 | 20000부터 60개 | v0 | 60개 중 59개 | 5.40초 | 1.93발 |
| 신경 초파리, 자극 켬 | 20000부터 60개 | v1 | 180개 중 164개 | 4.06초 | 2.04발 |

v1로 정한 기준은 재기 전에 적어 두었다. 규칙 초파리 에피소드 200개에서 v0보다 빠를 확률이 0.90 이상이고, 포획률이 97% 아래로 내려가지 않아야 한다. 확률은 1.000이고 포획률은 97.3%다. 신경 초파리 결과는 판정에 쓰지 않고 그대로 적기로 했다. 판정 기준과 결과는 [판정 문서](docs/issues/feature/72-feature-aimer-v1-sac-rule-trigger/gate.md)에, 에피소드별, 발별 원자료와 다시 재는 명령은 [data 폴더](docs/issues/feature/72-feature-aimer-v1-sac-rule-trigger/data/README.md)에 있다.

v1을 돌리려면 #51의 모델 폴더를 가리킨다.

```sh
uv run python scripts/match.py --aimer baseline --aimer runs/2026-11-15_151701_sac-beam-assist-s0
uv run python scripts/record_match.py runs/2026-11-15_151701_sac-beam-assist-s0 --fly-model neural
```

모델 파일은 저장소에 없다. `runs/`는 git에 올리지 않기 때문이다.

### 각가속도로 학습한 조준기

추적 보조 없이 정책 혼자 조준하는 조준기는 #51에서 600개 가운데 21개만 잡았다. 정책이 0.02초마다 각속도를 새로 내서 거의 매 step 방향이 뒤집혔고, 조준기는 각가속도 한계 때문에 그 명령을 따라가지 못했다. #88에서는 정책이 각가속도를 내게 했다(`--control accel`). 환경과 포획 조건은 그대로다.

환경 버전 6에서 규칙 초파리 상대로 SAC를 1,000,000 step씩, 조건마다 학습 seed 0, 1, 2로 학습했다. seed 20000부터 에피소드 200개에서 2026-11-26에 쟀고, 값은 모델 셋의 평균이다. 평균 시간은 놓친 에피소드를 10초로 쳐서 냈다. 추적 보조는 모두 없다.

| 돌리는 행동 | 쏘는 방식 | 보상에서 바꾼 것 | 포획 | 평균 시간 | 에피소드마다 오발 |
|---|---|---|---|---|---|
| 각속도 | 기준선의 규칙 | 없음 | 600개 중 12개 | 9.97초 | 19.58발 |
| 각가속도 | 기준선의 규칙 | 없음 | 600개 중 579개 | 3.02초 | 0.69발 |
| 각가속도 | 기준선의 규칙 | 행동 변화 벌점 1.0 | 600개 중 589개 | 2.61초 | 0.47발 |
| 각가속도 | 정책이 정함 | 오발 벌점 0.3 | 600개 중 0개 | 10.00초 | 0.007발 |
| 각가속도 | 정책이 정함 | 오발 벌점 1.0 | 600개 중 0개 | 10.00초 | 0.007발 |

같은 에피소드에서 v0은 200개 중 198개를 4.89초에, v1은 600개 중 584개를 3.03초에 잡는다. 재기 전에 적어 둔 기준(v0보다 빠를 확률 0.90 이상, 포획률 97% 이상)을 넘은 것은 셋째 조건뿐이다. 둘째 조건은 포획률이 96.5%라 기준에 못 미쳤다. 셋째 조건이 v1을 대신할지는 따로 견주지 않았다.

쏘는 것까지 함께 학습한 두 조건은 조준은 배웠지만 거의 쏘지 않는다. 그래서 조준을 셋째 조건의 모델에 고정하고 쏘는 것만 500,000 step 학습했다(`--aim`). 네 조건 모두 쏘고 잡지만, 같은 조준 모델에 기준선의 규칙을 붙인 것보다 0.03~0.23초 느리다. 규칙은 포획 조건을 그대로 옮긴 것이라 시간으로는 이길 여지가 거의 없었다.

판정 기준과 결과는 [조준 판정 문서](docs/issues/feature/88-feature-aimer-accel-action-sac-fire/gate.md)와 [발사 판정 문서](docs/issues/feature/88-feature-aimer-accel-action-sac-fire/gate-fire.md)에, 조건의 뜻과 진단은 [조건 문서](docs/issues/feature/88-feature-aimer-accel-action-sac-fire/conditions.md)에, 원자료와 다시 재는 명령은 [data 폴더](docs/issues/feature/88-feature-aimer-accel-action-sac-fire/data/README.md)에 있다.

### 대전표

조준기와 초파리를 번갈아 학습하면 단계마다 새 모델이 하나씩 나온다. 이 README는 그 모델에 조준기 v1, 초파리 v1처럼 번호를 붙이고, 사람이 짠 규칙인 기준선과 규칙 초파리를 v0으로 친다. 이 번호는 환경 버전과 다르다.

`match.py`는 조준기 모델을 행, 초파리 모델을 열로 놓고 맞붙인 표를 출력한다. 칸마다 같은 seed로 에피소드를 돌려 포획 수와 포획까지 평균 시간을 적는다. 평균 시간은 포획한 에피소드만으로 낸다. 기본은 seed 10000부터 200개다. seed가 맞춰 주는 것은 시작 위치까지다. 초파리 agent는 레이저 빔을 보고 피하므로, 같은 seed라도 조준기가 다르면 초파리 경로가 다르다.

```sh
uv run python scripts/match.py --aimer baseline --aimer runs/<조준기 실행 id> --fly rule --fly runs/<초파리 실행 id>
```

```
환경 버전 5, seed 10000~10199 (칸마다 에피소드 200개)

| 조준기 \ 초파리 | rule | <초파리 실행 id> |
|---|---|---|
| baseline | 200/200, 4.95초 | … |
| <조준기 실행 id> | … | … |
```

`--aimer`와 `--fly`는 여러 번 줄 수 있고, 실행 폴더나 checkpoint 파일을 받는다. 조준기 v0은 `baseline`, 초파리 v0은 `rule`로 가리키고, 아무것도 주지 않으면 이 둘만 맞붙인다. `--json 파일`을 주면 결과를 JSON으로도 저장한다. 환경 버전이 지금 코드와 다른 모델이 하나라도 있으면 표를 만들지 않고 멈춘다. 환경 버전 5에서 학습한 조준기 모델만은 받는다. 이 모델은 조준만 하고, 쏠지는 기준선의 쏘는 규칙이 정한다. 표에는 이름 뒤에 `+rule-fire`가 붙는다.

조준기와 초파리는 한쪽을 고정해 두고 번갈아 학습한다. 순서는 이렇고, 번호는 단계마다 하나씩 오른다.

1. 조준기 v1: 초파리 v0을 상대로 학습한다.
2. 초파리 v1: 조준기 v1을 상대로 학습한다.
3. 조준기 v2: 초파리 v1을 상대로 학습한다.
4. 2와 3을 되풀이한다.

새 모델이 나올 때마다 대전표에 행이나 열을 하나 더한다. v0 행과 v0 열은 끝까지 남긴다. 상대가 계속 바뀌어도 이 두 줄은 그대로라서, 실력이 정말 늘었는지는 여기서 본다. 새 조준기가 최신 초파리는 잡는데 v0 열에서 성적이 떨어지면, 예전 상대를 잡는 법을 잊은 것이다.

### 실행 폴더

실행마다 `runs/` 아래에 폴더 하나가 생긴다. `runs/`는 git에 올리지 않는다.

```
runs/
  index.json                    실행 목록
  <실행 id>/                    예: 2026-11-09_130439_baseline
    config.json                 환경 버전, 환경 설정 전체, 알고리즘 설정
    episodes.json               에피소드 목록과 각 요약
    episodes/<tag>/ep_000.json  에피소드 하나
    checkpoints/<tag>.zip       checkpoint (학습만)
    model.zip                   마지막 모델 (학습만)
    tb/                         TensorBoard 기록 (학습만)
```

`<tag>`는 실행 안에서 에피소드를 나누는 이름이다. 기준선이면 `baseline`, 학습이면 평가한 시점까지의 step 수다(`step_0020000` 형식). 학습 시작 때는 `step_0000000`이고, viewer에서는 "학습 전"이다.

환경 버전은 `config.json`의 `envVersion`이다. 관측, 행동, 보상, 물리 제한처럼 학습한 모델이 기대는 가정을 코드에서 바꾸면 `flytracker/env.py`의 `ENV_VERSION`을 올린다. 옵션이나 설정으로 실행마다 바꾼 값은 버전을 올리지 않고 `config.json`의 환경 설정에 남는다. 버전이 다른 실행끼리는 성적을 견주지 않는다. 버전마다 무엇이 바뀌었는지는 `ENV_VERSION` 위 주석에 적는다. `envVersion`이 없는 실행은 버전 1이다.

학습 실행의 `config.json`에는 어느 쪽을 학습했는지(`algo.side`)와 상대가 누구였는지(`algo.opponent`)도 적힌다.

### 실행 올리기

팀과 나눌 실행은 `published/`에 복사해 PR로 올린다. 학습한 실행 폴더에는 모델 파일과 TensorBoard 기록이 함께 들어 있어서 `runs/`는 통째로 올리지 않는다. `publish_run.py`는 설정과 에피소드 파일만 복사한다. 이미 올린 실행을 다시 복사하려면 `--force`를 붙인다.

```sh
uv run python scripts/publish_run.py 2026-11-11_133858_baseline --issue 22
git add published/2026-11-11_133858_baseline
```

`--issue`에는 그 실행이 속한 GitHub issue 번호를 적고, 빠뜨리면 복사하지 않는다. viewer가 실행을 issue별로 묶어 보여 주기 때문이다. 스크립트는 `gh`로 issue의 제목과 주소를 읽고, 올린 사람은 `git config user.name`에서 가져와 `run.json`에 적는다. 그래서 [GitHub CLI](https://cli.github.com/)(`gh`)에 로그인되어 있어야 한다.

학습 결과를 올리는 issue에는 `training` label을 붙인다. GitHub에서 학습 issue만 골라 보려는 표시다. label이 없는 issue 번호를 주면 스크립트가 경고하지만 복사는 한다.

실행을 올린 issue마다 설명 파일 `published/issues/<issue 번호>.json`을 하나 쓴다. viewer의 [issue 화면](#issue-화면)에 나오는 실험 단계와 실험 이유는 실행 기록에 남지 않아서 사람이 적어야 한다. 파일이 없으면 `publish_run.py`가 경고하고 `uv run pytest`가 실패한다. 화면에 그대로 나오는 글이고, README처럼 한다체로 쓴다. 예시는 `published/issues/35.json`이다.

| 항목 | 뜻 |
|---|---|
| `phase` | 실험 단계 한 줄. 예: `조준기 v1 학습` |
| `purpose` | 에피소드를 만든 이유. 문단 하나가 문자열 하나인 목록이다 |
| `aimer`, `fly` | 학습한 조준기와 학습한 초파리의 버전 표기. 예: `v1`. 번호는 [대전표](#대전표)의 규칙을 따른다. 기준선과 규칙 초파리는 적지 않아도 v0으로 나온다 |
| `compare` | 비교 대상 issue 번호. 예: `22`. 실행이 올라온 다른 issue여야 한다. 적지 않으면 비교하지 않는다 |
| `notes` | `config.json`에 없는 조건. `label`과 `value`를 가진 항목의 목록이다. 예: 에피소드 seed |

`phase`와 `purpose`는 꼭 쓰고, 나머지는 필요할 때만 쓴다.

`published/`는 `runs/`와 구조가 같다. 다만 `checkpoints/`, `model.zip`, `tb/`가 없고, `index.json` 대신 실행 폴더마다 `run.json`이 있다. `run.json`은 `runs/index.json`에 있던 그 실행의 한 줄에 issue(`issue`)와 올린 사람(`author`)을 더한 것이다. viewer를 build할 때 실행마다 있는 `run.json`을 모아 실행 목록을 만든다. 실행 목록을 한 파일에 두지 않으므로, 두 사람이 각자 실행을 올린 PR도 서로 충돌하지 않는다. PR이 main에 merge되면 [배포](#배포)한 viewer에 그 실행이 나온다.

### 정책의 기억

기준선은 탐색 상태를 안에 들고 있다. 8자를 몇 바퀴째 그리는지, yaw를 몇 바퀴 돌았는지 기억한다. MLP 정책은 그런 기억이 없다. 관측에서 지난 일을 알려 주는 항목은 마지막으로 본 방향과 놓친 뒤 지난 시간뿐이고, 놓친 뒤 지난 시간은 2초에서 멈춘다. 그래서 "이 pitch는 이미 훑었다"처럼 몇 초에 걸친 탐색을 배우기 어렵다.

정책에 기억을 주는 방법은 세 가지다.

- frame stack: `train.py --frame-stack N`으로 켠다. 최근 N step(N × 0.02초)의 관측을 함께 본다. 초파리가 움직이는 방향을 아는 데는 쓸 만하지만, 몇 초에 걸친 탐색을 기억하기에는 짧다.
- recurrent 정책(LSTM): Stable-Baselines3 확장 패키지 `sb3-contrib`의 RecurrentPPO가 필요하다. 지금 의존성(`pyproject.toml`)에는 없다.
- 관측에 기억 항목 더하기: 환경을 고치는 일이다.

코드를 고치지 않고 바로 쓸 수 있는 것은 frame stack뿐이다.

### 학습 시간

알고리즘마다 학습 속도가 열 배 넘게 차이 난다. SAC와 TD3는 step마다 신경망을 업데이트해서 느리다. 아래 표의 "실제 1초당 step"은 학습을 돌리는 컴퓨터가 실제 시간 1초에 처리하는 step 수다.

| 알고리즘 | 실제 1초당 step | 200,000 step(`train.py` 기본값)에 드는 시간 |
|---|---|---|
| SAC | 53 | 약 63분 |
| TD3 | 42 | 약 79분 |
| DQN | 611 | 약 5분 |
| PPO | 493 | 약 7분 |

Intel Core i9-13900H CPU에서 GPU 없이(`train.py` 기본값 `--device cpu`) Stable-Baselines3 기본 설정으로 2026-11-10에 잰 값이다. 알고리즘마다 30초~2분 남짓 학습을 돌려 속도를 재고, 그 속도로 200,000 step을 환산했다. 돌린 길이는 SAC와 TD3가 6,000 step, DQN이 20,000 step, PPO가 16,384 step이다. 학습 없이 환경만 돌리면 같은 CPU에서 실제 1초당 약 2,500 step이다. 그러니 학습 시간 대부분은 환경이 아니라 신경망 업데이트에 든다.

### 에피소드 파일의 한계

에피소드 파일에 남는 것은 환경이 아는 실제 상태다. 조준기 agent가 받은 관측 가운데 마지막으로 본 방향, 놓친 뒤 지난 시간, 조준기 각속도는 남지 않고, 조준기 agent가 고른 행동도 남지 않는다. 기준선은 어떤 경우에 어떻게 움직이는지가 코드에 규칙으로 적혀 있어서 코드를 읽으면 안다. 조준기 agent에는 그런 규칙이 없으므로, 이상하게 움직이는 이유를 찾으려면 에피소드 파일의 항목을 늘려야 한다.

## viewer

viewer는 Vite, React, React Three Fiber로 만든 웹 페이지다. 개발 서버가 저장소의 `runs/`와 `published/`를 `/runs` 주소로 내주므로 따로 백엔드가 없다. 같은 실행이 두 폴더에 다 있으면 목록에 한 번만 나온다.

```sh
npm install --prefix viewer
npm run dev --prefix viewer
```

브라우저에서 http://localhost:5180 을 연다. 처음에는 [계보](#계보)가 나온다. 실행을 고르면 화면이 왼쪽부터 실행 목록, 실행 패널, 재생 화면이 된다.

### 계보

계보는 issue가 어떤 순서로 이어졌는지를 한 화면에 그린 것이다. 세 세로줄이 초파리, 조준기, 환경이고, issue마다 노드 하나가 그 issue가 주로 바꾼 영역의 줄에 놓인다. 위에서 아래로 시간 순서다. 영역 이름 옆에는 그 영역의 지금 상태가 나온다. 환경은 가장 높은 환경 버전, 조준기는 마지막 조준기 버전, 초파리는 종류다.

버전을 올린 issue의 노드는 크게 그리고 맨 위에 "환경 버전 3", "조준기 v1" 같은 버전 표시를 단다. 초파리는 종류가 처음 나오는 노드에 "규칙 초파리", "신경 초파리"를 단다. 표시의 점은 영역마다 색이 다르다. 조준기 영역의 #45처럼 다른 영역의 버전을 올린 issue가 있으면, 그 버전이 제 영역의 같은 줄에도 "환경 버전 4 #45"로 놓인다. 그래서 환경 줄만 내려 읽어도 버전 1부터 6까지 이어진다. 버전을 올리지 않은 issue의 노드는 작게 그린다.

노드에는 issue 번호, 짧은 이름, 바뀐 값, 잰 수치, PR을 올린 사람과 merge한 날짜가 나온다. 바뀐 값은 "포획 조건 조준 오차 3° 안 0.2초 → 빔까지 1.25mm 안 0.15초"처럼 전과 후를 적은 한 줄이다. 수치의 "포획 5/200"은 에피소드 200개 가운데 5개를 포획했다는 뜻이다. 결과를 적은 문장은 노드에 마우스를 올리면 뜬다. 다른 영역도 함께 바꾼 issue에는 "조준기도 바꿈"이 붙는다.

선은 이어받은 issue에서 이어진 issue로 간다. 같은 영역 안에서는 아래로 곧게 가고, 영역이 다르면 줄 사이의 틈을 타고 내려간다. 환경의 #42(레이저 명중)에서 조준기의 #45(새 기준선)로 가는 선이 그런 예다. 노드에 마우스를 올리면 그 노드에 닿은 선만 파랗게 되고 이어지지 않은 노드는 흐려진다.

실행을 올린 issue의 노드를 누르면 [issue 화면](#issue-화면)이 열린다. 코드만 바꾸고 실행은 올리지 않은 issue는 점선 테두리로 흐리게 그리고, 누르면 GitHub의 그 issue가 새 창으로 열린다. 실행 목록 맨 위의 "계보"를 누르면 언제든 이 화면으로 돌아온다.

계보는 `viewer/src/data/lineage.js`에 손으로 적는다. issue마다 영역(`lane`), 이어받은 issue(`parents`), 이름(`name`), 결과(`result`)를 쓴다. `parents`는 설명 파일의 `compare`와 다르다. `compare`는 값을 견줄 대상이고 `parents`는 그 일이 어디서 나왔는지다. 제목, 올린 사람, merge 날짜는 `viewer/src/data/history.js`의 issue 표에서 온다. `name`은 그 issue에서 무엇이 어떻게 바뀌었는지를 15자 안쪽으로 적은 이름이다. 계보의 노드, 사이드바의 묶음, issue 화면의 제목이 모두 이 이름을 쓰고, GitHub의 issue 제목은 마우스를 올리면 나온다. 설명 파일의 `phase`와는 다르다. `phase`는 실험 계획에서의 자리다.

버전과 바뀐 값은 아래 칸에 적는다. 모두 해당할 때만 쓴다.

| 칸 | 내용 |
| --- | --- |
| `envVersion` | 그 issue가 올린 환경 버전 |
| `aimerVersion` | 그 issue에서 정해진 조준기 버전. `v0`은 기준선이고, 지금의 기준선 동작이 나온 #45에 적었다 |
| `fly` | 그 issue에서 계보에 처음 나오는 초파리 종류. `규칙 초파리`, `신경 초파리` |
| `change` | 바뀐 값 하나. `{ what: 무엇이, from: 전, to: 후 }`. 전이 없으면 `from`을 뺀다 |
| `metric` | 그 issue에서 잰 수치. `result`에 있는 숫자만 옮긴다 |

실행을 올린 issue가 계보에 없거나, 이름이 15자를 넘거나 다른 issue와 같거나, 환경 버전이 건너뛰면 `tests/test_viewer_lineage.py`가 실패한다.

### 실행 목록

실행은 issue별로 묶여 나오고, issue 묶음은 [계보](#계보)와 같은 세 영역인 초파리, 조준기, 환경 아래에 나뉘어 놓인다. 영역은 그 issue가 주로 바꾼 것 하나이고 `lineage.js`의 `lane`에서 온다. 다른 영역도 함께 바꾼 issue도 한 영역에만 나온다. 영역 안에서는 가장 최근 실행이 있는 issue가 위에 온다. issue 번호 없이 `runs/`에만 있는 실행은 세 영역 아래의 "issue 없음"에 모인다. 묶음은 처음에 모두 접혀 있다. issue 이름 줄을 누르면 묶음이 펼쳐지면서 [issue 화면](#issue-화면)이 열린다. 그 issue 화면을 보는 중에 다시 누르면 묶음이 접힌다. 묶음의 실행을 보는 중에 누르면 접히지 않고 issue 화면으로 간다.

묶음을 펼치면 실행이 한 줄에 하나씩 나온다. 줄에는 실행을 가르는 짧은 이름만 적는다. 조합이 둘 이상인 issue면 "A rule-baseline", "B 학습 seed 0"처럼 글자가 앞에 온다. 글자 뒤는 표의 실행 칸에 나오는 이름이다. [issue 화면](#issue-화면)의 표에서 그 조합을 부르는 글자이고, 검색으로 실행을 걸러도 바뀌지 않는다. 조합 안에 학습 seed만 다른 실행이 여럿이면 학습 seed이고, 아니면 실행 이름이다. 조합이 하나뿐인 issue에는 글자가 없다. 그 실행의 초파리, 조준기, 환경은 표에서 같은 글자의 줄을 보거나 줄에 마우스를 올려서 본다. 실행 이름, 올린 사람, 만든 때도 마우스를 올리면 나온다. 실행을 늘어놓는 순서는 표의 줄 순서와 같다.

실행마다 마지막 checkpoint의 포획률이 나온다. 포획률은 그 checkpoint의 평가 에피소드 가운데 포획으로 끝난 비율이다. checkpoint가 둘 이상이면 포획률이 학습 중에 어떻게 변했는지를 작은 선으로도 그린다. 검색 칸에는 실행 이름, issue 제목, `#22` 같은 issue 번호, 올린 사람, 알고리즘을 넣는다.

### 실행 패널

실행을 고르면 그 실행의 에피소드가 checkpoint별 목록으로 나온다. checkpoint는 위에서 아래로 학습이 진행된 순서다. checkpoint마다 제목 줄에 이름과 "2 / 3" 같은 포획 수가 나오고, 제목 줄을 누르면 에피소드가 펼쳐지거나 접힌다. 처음에는 고른 checkpoint만 펼쳐져 있다. 에피소드는 한 줄에 하나씩이고, 줄마다 번호, 결과(포획이면 걸린 시간), 누적 보상이 나온다.

줄을 누르면 그 에피소드가 재생된다. 목록 안에서는 위아래 화살표 키로 앞뒤 에피소드로 옮기고, 스페이스로 멈추거나 다시 재생한다. 좌우 화살표 키는 번호가 같은 에피소드를 앞뒤 checkpoint에서 연다. 평가는 checkpoint마다 같은 seed를 쓰므로([학습](#학습)), 번호가 같은 에피소드는 같은 초파리를 상대한 것이다. 그래서 좌우로 옮기면 학습이 그 에피소드의 결과를 어떻게 바꿨는지 보인다.

패널 맨 위에는 그 실행의 조합이 초파리, 조준기, 환경 순서로 나온다. 내용은 [issue 화면](#issue-화면)의 조합 표에서 그 실행이 든 줄과 같고, 학습 seed가 있으면 조준기 줄에 붙는다. 조합이 둘 이상인 issue면 맨 위에 표에서 그 줄을 부르는 글자가 "실험 A"처럼 나온다. 그 아래에는 고른 checkpoint의 포획률, 평균 보상, 포획 시간과 학습 곡선이 있다. 곡선의 점을 누르면 그 checkpoint로 간다. checkpoint가 하나뿐인 실행(기준선)에는 학습 곡선이 없다. 학습 곡선은 가로축이 step이고 세로축은 포획률과 평균 보상 가운데 고른 값이다.

### 재생 화면

3인칭 장면, 조준기 화면, 확대 화면, 현재 상태, 누적 보상과 조준 오차 그래프가 나온다. 조준기 화면 가운데의 십자는 빔이 지나는 자리이고, 현재 상태에는 빔까지 거리가 나온다. 에피소드는 고르면 바로 재생된다. 목록 밖에서는 스페이스로 멈추거나 다시 재생하고, 화살표 키로 한 프레임씩 옮긴다. 그래프를 누르면 그 시각으로 간다.

확대 화면은 조준기 화면의 가운데를 80배로 키운 것이다. 세로 0.5°, 가로 1° 범위를 보여 주며, 2m 거리에서는 가로 약 35mm다. 가운데 원은 초파리가 있는 거리에서 빔(지름 2.5mm)이 차지하는 범위이고, 맞는 동안 초록색이 된다. 환경 버전 2까지의 에피소드는 십자 대신 포획 각도 3°를 원으로 그리고, 확대 화면과 빔까지 거리는 나오지 않는다.

레이저를 쏠 때만 켜는 에피소드(환경 버전 6부터)는 조준선과 빔을 따로 그린다. 조준선은 늘 옅은 선이다. 빔은 쏘는 0.15초 동안에만 나타나는 굵은 막대이고, 초파리 위에 있으면 초록색으로 초파리까지, 벗어났으면 붉은색으로 벽까지 간다. 실제 빔 지름 2.5mm는 3인칭 장면에서 보이지 않아서 굵기를 키워 그렸다. 같은 순간에 조준기 화면 가운데에는 빛나는 점이 켜지고 확대 화면의 원은 색으로 채워진다. 발이 끝까지 맞아 포획이 되면 초파리 자리에 고리가 생기고 현재 상태가 "명중"이 된다. 발이 끝나기 전에는 "맞는 중", 빔이 벗어났으면 "오발"이다. 재생 막대 아래에는 발마다 표시가 하나씩 있다. 자리와 길이는 그 발을 쏜 시간이고, 명중은 초록색, 오발은 붉은색이다. 표시를 누르면 그 발이 시작한 때로 간다. 환경 버전 5까지의 에피소드는 전과 같이 조준선 하나로 그리고 상태는 "포획 중"이다.

### issue 화면

실행 목록에서 issue 제목을 누르면 그 issue가 어떤 실험인지 보여 주는 화면이 열린다. 위에서부터 실험, 조합 표, 초파리와 조준기, 환경, 학습 곡선이 나온다. 실행 하나하나는 조합 표나 실행 목록에서 고른다.

실험 칸에는 실험 단계와 에피소드를 만든 이유가 나온다. [실행 올리기](#실행-올리기)에서 쓴 설명 파일의 `phase`와 `purpose`다. 설명 파일에 `compare`가 있으면 그 아래에 비교 대상 issue가 나오고, 누르면 그 issue 화면으로 간다.

조합 표는 "실험 목록"이라는 제목 아래에 있고, 그 issue의 실행이 어떤 초파리, 조준기, 환경으로 돌았는지를 보여 준다. 줄 하나가 조합 하나이고 칸은 늘 실험, 초파리, 조준기, 환경, 실행 순서다. 실험 칸의 A, B, C는 그 줄을 부르는 글자다. 줄은 칸 순서대로 초파리, 조준기, 환경의 글자 순서로 놓여서 같은 초파리의 줄이 모인다. 글자는 줄 순서대로 붙이므로 실행이 새로 올라오면 바뀔 수 있다. 학습 seed만 다른 실행은 같은 설정을 되풀이한 것이라 한 조합으로 묶는다. #72라면 조준기 둘(기준선 v0, 학습한 조준기 v1)과 초파리 셋(규칙 초파리, 신경 초파리 자극 끔, 자극 켬)이 만나 여섯 줄이다. 칸의 윗줄은 종류와 버전이고, 종류가 같은 조합끼리 값이 다른 설정만 그 아래에 이름과 값으로 나온다. #35라면 두 줄 모두 학습한 조준기이고 그 아래에 "함께 보는 최근 관측 1개"와 "4개"가 붙는다. 모든 조합에서 같은 값은 표에 나오지 않고 아래의 초파리, 조준기, 환경 칸에 나온다.

실행 칸에는 그 조합의 실행이 버튼으로 나온다. 학습 seed만 다른 실행이 여럿이면 "학습 seed 0", 아니면 실행 이름이고, 옆의 "3/3"은 마지막 checkpoint의 에피소드 가운데 포획한 수다. 관찰 기록은 에피소드 수만 나온다. 버튼을 누르면 그 실행이 열린다. 조합이 둘 이상이면 표의 줄을 눌러 조합을 고른다. 고르면 그 아래 칸과 학습 곡선이 그 조합의 실행만으로 바뀌고, 고른 줄을 다시 누르면 전체로 돌아간다.

초파리와 조준기 칸에는 종류, 버전, 짧은 설명이 나온다. 종류는 규칙 초파리, 학습한 초파리, 기준선, 학습한 조준기 가운데 하나다. 학습한 쪽이면 알고리즘, 학습 step, 학습 seed, 함께 보는 최근 관측 수(frame stack)도 나온다. 다른 환경 버전에서 학습한 모델을 돌린 실행이면 학습한 환경 버전과 모델의 실행 id도 나온다. 기준선에는 따라가는 방식이 나온다. 기준선은 환경 버전 4(#45)부터 초파리 방향의 각속도에 맞춰 돌고, 그 전에는 조준 오차만 보고 돌았다.

종류 카드 아래에는 설정 카드와 보상 카드가 붙는다. 값마다 주인이 있어서, 초파리의 비행과 감각은 초파리 칸에, 조준기의 몸과 화면은 조준기 칸에, 양쪽에 똑같이 적용되는 규칙은 환경 칸에 둔다.

| 칸 | 카드 | 나오는 줄 |
|---|---|---|
| 초파리 | 설정 | 규칙 초파리와 학습한 초파리는 비행 속도, 급선회 각도와 시간, 피할 때 속도. 규칙 초파리는 위협을 느끼는 거리, 무조건 피하는 거리, 반응 지연도. 학습한 초파리는 관측 지연도. 신경 초파리는 가상 자극의 값 |
| 초파리 | 보상 | 학습한 초파리 보상의 가중치. 학습한 초파리가 있는 실행에서만 나온다 |
| 조준기 | 설정 | 조준기 자리, 시야각, 확대 화면 배율, 좌우와 위아래 회전 속도, 각가속도, 위아래 조준 한계, 시작 방향 |
| 조준기 | 보상 | 조준기 보상의 가중치. 항목의 뜻은 [조준기의 R](#조준기의-r)에 있다 |

환경 칸에는 환경 버전, 방 크기, 에피소드 길이, 포획 범위, 포획 유지 시간, 초파리 시작 거리, 실행과 에피소드 수가 나오고, 그 아래에 설명 파일의 `notes`가 붙는다. 포획 조건은 조준기가 맞히는 것이지만 승패를 정하는 규칙이라 환경에 둔다. 초파리, 조준기, 환경은 실행마다 `config.json`에서 읽는다. 실행끼리 값이 다르면 `0, 1, 2`처럼 나란히 적는다.

비교 대상이 있으면 초파리, 조준기, 환경 칸이 저마다 비교 대상 issue의 실행 전체와 견준 결과를 보여 준다. 초파리나 조준기의 종류나 버전이 바뀌었으면 카드의 비교 대상 줄에 이전 종류가 나오고, 그대로면 "같음"이 나온다. 값이 바뀐 줄은 이름 앞에 파란 점이 붙고 "0.2초 → 0.15초"처럼 비교 대상의 값과 지금 값을 함께 보여 준다. 같은 단위의 수가 바뀌었으면 "−0.05초"처럼 차이도 적는다. 실행과 에피소드 수, 설명 파일의 `notes`는 견주지 않는다. 한쪽에만 있는 카드도 견주지 않는다. 비교 대상에 학습한 초파리가 없었다면 초파리 보상은 바뀐 것이 아니라 새로 생긴 것이기 때문이다.

줄이나 카드 이름에 마우스를 올리면 그 값을 정한 issue가 상자로 뜬다. issue 번호와 제목, PR을 올린 사람, merge한 날짜, 그렇게 정한 이유가 나온다. 누르면 GitHub의 그 issue가 새 창으로 열린다. 같은 줄이라도 환경 버전에 따라 가리키는 issue가 다르다. 포획 범위는 환경 버전 2의 실행에서는 #1을, 환경 버전 3부터는 #42를 가리킨다. 이 표는 `viewer/src/data/history.js`에 손으로 적어 둔 것이라, 기본값이나 뜻을 바꾸는 issue를 merge할 때 한 줄을 더해야 한다. 줄을 새로 만들고 표에 적지 않으면 `tests/test_viewer_experiment.py`가 실패한다.

학습 곡선은 step이 있는 실행이 있을 때만 나온다. 실행들의 곡선을 겹쳐 그리고, step이 없는 실행(기준선)은 점선 가로줄이다. 어느 선이 어느 실행인지는 곡선 아래의 색 점과 실행 이름이 알려 준다.

### 링크

무엇을 골랐는지는 주소에 남는다. 주소를 복사해 PR이나 issue 댓글에 붙이면 받은 사람에게 같은 에피소드가 열린다.

| 주소 | 열리는 것 |
|---|---|
| `/?run=<실행 폴더 이름>&tag=<tag>&ep=<번호>` | 그 실행의 그 에피소드. `ep`는 1부터 센다 |
| `/?issue=<issue 번호>` | 그 issue의 비교 화면 |

아무것도 가리키지 않는 주소(`/`)와 없는 실행이나 issue를 가리키는 주소는 계보를 연다.

### 초파리 3D 모델

초파리는 3인칭 장면과 조준기 화면 모두 실제 모양과 크기(몸 길이 약 3mm)로 그린다. 3D 모델은 [flybody](https://github.com/TuragaLab/flybody)(Apache-2.0)의 메시를 줄여 만들었고, 만드는 법은 `scripts/build_fly_model.py`, 출처는 `viewer/public/models/fruitfly.NOTICE.txt`에 있다. 실제 크기로는 화소 하나보다 작아서, 3인칭 장면에서는 지나온 궤적으로 위치를 본다.

### 조준기 화면의 사각형

조준기 화면 위의 사각형은 Python이 기록한 화면 좌표 자리에 그린 표식이다. 조준기 화면에서는 초파리가 멀면 화소보다 작아 눈에 띄지 않으므로 위치는 이 사각형으로 본다. 3D로 그린 초파리와 사각형이 어긋나면 Python의 투영 계산과 viewer 중 한쪽이 틀린 것이다.

### 배포

viewer는 https://flytracker-ewk.pages.dev/ 에 올라가 있다. Cloudflare Pages가 저장소에 연결되어 있어서, main에 merge할 때마다 viewer를 다시 build해 올린다. build 결과물(`viewer/dist/`)에는 `published/`의 실행만 들어가고 `runs/`는 들어가지 않는다. PR을 올리면 미리보기 주소가 따로 생기므로, merge 전에 올린 실행을 재생해 볼 수 있다.

사이트에 올라갈 결과물은 내 컴퓨터에서도 미리 볼 수 있다. preview 서버는 개발 서버와 달리 `dist/`만 내준다.

```sh
npm run build --prefix viewer
npm run preview --prefix viewer
```

Cloudflare Pages 프로젝트 `flytracker`는 아래처럼 설정되어 있다. 새 프로젝트를 만들 때 dashboard의 Create application 화면에 Pages가 보이지 않으면, 화면 아래 Pages 링크나 `https://dash.cloudflare.com/?to=/:account/workers-and-pages/create/pages`로 들어간다.

| 항목 | 값 |
|---|---|
| Production branch | `main` |
| Root directory | `viewer` |
| Build command | `npm run build` |
| Build output directory | `dist` |
| 환경 변수 | `NODE_VERSION` = `22` |
